# @repoassure/design-system

RepoAssure Design System v2, vendored for use by both product surfaces: the public website (`apps/website`) and the Project Intelligence Console (generated by `packages/acceptance`).

Adopted by [ADR-0046](../../docs/adr/0046-repoassure-design-system-v2-and-information-architecture.md).

## Layout

```
index.js / index.d.ts     component barrel — 37 React primitives
css.js  / css.d.ts        flattened CSS string for standalone HTML surfaces
components/               core · layout · navigation · forms · data · feedback
styles/
  index.css               token + base layer, loads no fonts
  fonts.css               self-hosted brand faces, opt-in
  tokens/                 colors · typography · spacing · effects
  base.css
assets/                   logo-lockup.svg · logo-mark.svg · og-image.svg
```

## Token architecture

Three layers, Primer-inspired:

1. **Primitive scales** — raw hues (`--ink-*`, `--green-*`, `--blue-*`, `--red-*`, `--amber-*`, `--violet-*`). Components never read these.
2. **Semantic tokens** — theme-aware, the only layer components read (`--fg-default`, `--accent-fg`, `--danger-muted`, …).
3. **Console tokens** — theme-independent, for the always-dark evidence surface (`--console-bg`, `--console-fg`, …).

Light is the default theme on `:root`. Dark is opt-in via `[data-theme="dark"]`.

## Consuming it

**React surfaces** import components and both stylesheets:

```js
import '@repoassure/design-system/styles';
import '@repoassure/design-system/styles/fonts';
import { StatusChip, Terminal, ScoreGauge } from '@repoassure/design-system';
```

**Standalone HTML surfaces** inline the CSS instead, because they have no bundler to resolve `@import` and must not emit external references:

```js
import { readDesignSystemCss } from '@repoassure/design-system/css';

const html = `<style>${readDesignSystemCss()}</style>`;
```

## Deviations from the design system as supplied

Two, both deliberate and both recorded in ADR-0022.

**Fonts are self-hosted.** Upstream `tokens/fonts.css` was a single `@import` from Google Fonts. Shipping that would put a third-party network request on every page load of a product whose central claim is that nothing leaves your machine. The Latin faces — Space Grotesk, Hanken Grotesk, JetBrains Mono — are served from `@fontsource` packages instead.

Font loading is also split out of `styles/index.css` into `styles/fonts.css` so the Console can take the token layer without it. `tests/unit/project-intelligence-viewer.test.ts` asserts that generated console output contains no `http://` or `https://`, and the console HTML is opened over `file://`, where relative font URLs would not resolve.

**CJK resolves to the reader's system face.** Upstream listed `'Noto Sans SC'` as a webfont in every sans stack. The `@fontsource/noto-sans-sc` package is 71.6 MB — more than twenty times the three Latin families combined — because it covers the full Han repertoire. Vendoring it into a repository whose product claim is auditable local-first is untenable. The stacks now fall through to PingFang SC, Hiragino Sans GB, Microsoft YaHei, and Noto Sans CJK SC, which cover macOS, Windows, Android, and Linux respectively. `'Noto Sans SC'` is retained at the end of each stack so readers who happen to have it installed still get it.

## Inlining the SVG assets

The three files in `assets/` are standalone SVG documents, so each carries an
`xmlns="http://www.w3.org/2000/svg"` attribute. That is an XML namespace identifier,
not a network fetch — nothing is requested from `w3.org` at render time.

It still matters for the Console. Inline SVG inside an HTML document does not need the
attribute, and `tests/unit/project-intelligence-viewer.test.ts` matches on the literal
substring `http://`. Strip `xmlns` when embedding these into generated HTML, or the
assertion fails on a string that was never a reference.

## Note on the `--signed-*` tokens

`tokens/colors.css` defines a violet `--signed-*` family, and `StatusChip` exposes a `signed` status. Nothing in the product signs anything: emitted manifests carry no hash, signature, checksum, or digest field. ADR-0022 replaces that vocabulary with content hashing and independently verifiable integrity.

These tokens are vendored unchanged here so that this package is a faithful copy of what was supplied. Renaming them belongs to `repoassure-evidence-integrity-hashing-v0.1`, alongside the implementation and the copy change, so the rename lands with the thing that makes it true.
