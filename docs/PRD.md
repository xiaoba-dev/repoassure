## Product Intent

RepoAssure is a local-first AI code delivery assurance layer. It helps owners of AI-generated repositories turn uncertain code into reviewable, repairable, and shippable engineering evidence.

The current implementation still uses `hardening-mcp` as the internal package, CLI, and MCP implementation name while RepoAssure is the public product brand.

## Long-Term Vision and Strategic Pillars

The owner-confirmed long-term vision is for RepoAssure to become
provider-neutral, local-first acceptance infrastructure for AI-generated
software and AI-assisted contributions across coding agents, repository
platforms, and evidence providers. This is a future direction; the current
product truth remains the narrower local-first AI code delivery assurance layer
described above.

The strategy has three pillars:

1. An open acceptance evidence kernel and local reference engine, not a
   universal detector or a replacement for every test and security provider.
2. A maintainer-first, opt-in contribution network measured by accepted
   outcomes, not a bulk scanning or pull-request robot.
3. Open Core for adoption and ecosystem trust, with future Team Cloud and
   Enterprise value in shared evidence history, collaboration, policy, audit,
   identity, retention, and private control.

The owner-confirmed strategy, candidate three-year roadmap, impact flywheel,
commercial boundary, and explicit non-authorization rules are recorded in
[RepoAssure Unified Long-Term Product Strategy v0.1](product/strategy/repoassure-unified-long-term-strategy-v0.1.md).
It does not claim a formal external standard, global reach, Team Cloud or
Enterprise availability, or authorization to discover, acquire, execute,
contact, write, or open a pull request against any target repository.

## Target Users

- Individual AI builders who need a repeatable local hardening workflow before shipping generated repos.
- Engineering teams that need content-hashed evidence, repair plans, and acceptance decisions.
- AI IDE users who need an actionable repair decision package instead of a generic audit report.
- Future Team Cloud / Enterprise evaluators, with those capabilities explicitly marked as planned rather than available.
