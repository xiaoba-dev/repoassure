## System Boundary

RepoAssure currently consists of:

- CLI + MCP Server: local-first hardening runtime under `src/`, `apps/cli`, and `apps/mcp-server`.
- Workspace packages: `packages/acceptance`, `packages/shared`, `packages/security-assurance`, `packages/browser-explorer`, and `packages/repair-planner`.
- Public Website: React + Vite app under `apps/website`.
- Documentation and release governance: ADRs, operations records, acceptance records, testing strategy, and release boundary docs.
- Autopilot runtime state: `.autopilot/` machine-readable progress and goal records, with human source-of-truth remaining in `docs/`.

## Long-Term Strategic Architecture Boundary

[RepoAssure Unified Long-Term Product Strategy v0.1](product/strategy/repoassure-unified-long-term-strategy-v0.1.md)
defines an owner-confirmed target architecture without changing any current
runtime contract:

| Layer | Direction | Current boundary |
| --- | --- | --- |
| Open acceptance evidence kernel | Normalize portable evidence from agents, tests, scanners, provenance systems, runtimes, and human review. | Current RepoAssure schemas and artifacts remain authoritative; no formal external standard or universal-detector claim exists. |
| Local reference engine | Keep evidence generation, integrity verification, repair handoff, and acceptance review usable locally. | Existing CLI/MCP and package contracts remain unchanged by the strategy record. |
| Maintainer contribution network | In the future, allow only opt-in or policy-authorized, evidence-backed contribution workflows with independent acquisition, execution, and write approvals. | No target discovery, access, cloning, analysis, execution, contact, write, or pull-request workflow is implemented or authorized. |
| Commercial control planes | In the future, layer Team Cloud history/collaboration and Enterprise policy/audit/private control above the open artifact contract. | No Team Cloud or Enterprise runtime, hosted availability, source upload, pricing, deployment, or launch is implemented or authorized. |

Potential mappings to SARIF, SLSA, in-toto, and similar evidence ecosystems are
research candidates, not current compatibility or conformance claims. Every
roadmap milestone remains subject to a separate accepted spec, Goal, evidence
gate, and authorization.

## Applicability Boundary

RepoAssure Product Applicability Boundary Documentation Cascade v0.1 is completed with conclusion `product_applicability_boundary_documented`. The solution boundary now treats RepoAssure as first-class for AI-generated software projects that can be verified through local code, commands, tests, browser/CLI flows, logs, and evidence packages.

Core product types are Web App, CLI, AI IDE repair loop, and MCP / Agent tooling. Extended product types are Backend API, SDK / Library, Browser Extension, and Desktop App. Partner / Plugin types are Mobile App, AI Model Evaluation, Data Pipeline, and Security integrations. Out of Scope types are Hardware, Pure Design, Pure Docs, and Offline Business Process unless a later accepted spec adds a dedicated adapter.

This cascade does not implement runtime detector behavior changes and does not authorize claims that RepoAssure applies to every product, provides full-stack universal automatic acceptance, replaces human acceptance, or automatically fixes every AI code issue.
